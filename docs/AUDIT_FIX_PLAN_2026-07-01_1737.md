## Audit Summary

### 1. AI Integration — broken, isolated bug
`services/ai/docking_expert.py:55,83,105,129` calls `self.ai.query(prompt, temperature=0.X)`. `AIProviderManager.query()` (`services/ai/provider_manager.py:254`) does not accept a `temperature` kwarg. Every AI Expert action on `templates/pose_analysis.html` (Explain Pose, Compare Poses, Suggest Improvements, Generate Report) throws `TypeError` server-side.

All four provider API keys (OpenRouter, DeepSeek, Groq, Gemini) are present in `.env` and the provider-selection UI in `templates/settings.html` works. This is a code bug, not a config/credentials problem.

Secondary issue: `expert_service = DockingExpertService()` is instantiated at module import time in `api/routes/llm_explanation.py:70`. If provider init ever throws, the whole `/api/llm` router — and possibly app startup — fails.

### 2. Docking live 3D viewer — broken, FIXED (root cause was deeper than initially thought)
`templates/docking_workspace.html` passes raw PDBQT-flavored atom lines into Mol*'s strict PDB parser (`renderProteinPreview()`, ~line 1454–1497), which hangs (there's a 15s `Promise.race` timeout wrapped around the load call as a symptom patch, not a real fix). Porting `pose_analysis.html`'s `stripPdbqtToPdb()` helper (truncate ATOM/HETATM lines to column 66) is necessary but **was not sufficient** — live browser testing after applying it still hung on every load, even for a trivial 2-atom valid PDB with no PDBQT content at all.

**Actual root cause, found via live testing (not static analysis):** `molstarViewer` was stored as a top-level Alpine `x-data` property (`molstarViewer: null` at the original line 739). Alpine wraps every `x-data` property in a reactive Proxy. The Mol* `Viewer` object is a complex stateful instance (RxJS observables, internal state machines, a live WebGL/canvas context) whose internal `this`-bound async behavior breaks when accessed through that Proxy — confirmed empirically: an identical `Viewer.create()` + `loadStructureFromData()` call succeeds in under 250ms when the viewer reference is a plain JS variable, and hangs indefinitely (even a `Promise.race` timeout's own `setTimeout` couldn't preempt it) when the same object is read back through `this.molstarViewer`. This is a known category of bug with Proxy-based reactivity frameworks (Vue/Alpine) wrapping third-party stateful library instances (Mol*, Chart.js, Leaflet, etc.) — the fix is to never let the framework's reactivity system touch the instance.

**Fix applied** (`templates/docking_workspace.html`):
1. Added `stripPdbqtToPdb()` (ported from `pose_analysis.html`) and applied it to both the protein and ligand loads.
2. Introduced a module-level, non-reactive `let rawMolstarViewer = null` (declared outside `Alpine.data(...)`, in the shared `alpine:init` closure) to hold the actual Mol* `Viewer` instance. `this.molstarViewer` is now purely a boolean flag (`true`/`null`) used only by template bindings (`:class="{'opacity-0': !molstarViewer}"`) and boolean guards — every method that needs to call the real viewer's API (`ensureMolstarViewer`, `clearMolstarScene`, `clearMolstarHighlight`, `highlightSelectedPocket`, `renderProteinPreview`) now reads/writes `rawMolstarViewer` directly.
3. Added recovery: if a load fails/times out, the viewer is disposed and `rawMolstarViewer`/`this.molstarViewer` are reset to `null` so the next render creates a fresh instance instead of reusing a now-unreliable one.
4. Re-enabled four previously-disabled re-render call sites (`togglePreviewSetting()`, post-ligand-prep, `saveGridbox()`, `scheduleGridBoxUpdate()`) that a prior debugging session had commented out with "TEMP ISOLATION TEST" markers while chasing this exact hang — they're safe now that the underlying cause is fixed.

**Verified live** (via direct browser evaluation against the running dev server): a real 3687-atom receptor PDBQT (with genuine `OA`/`HD` PDBQT atom types) now loads in ~130–713ms with no error, and the Mol* canvas/controls render visibly in the panel. Before the fix, the identical file hung for 8+ seconds and left the viewer instance permanently broken for the rest of the page session.
